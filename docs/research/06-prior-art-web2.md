# Prior art: подключение web2-мерчантов к агентским/крипто-рельсам

2026-08-25, трек A. Синтез двух исследований (Opus-субагенты, ~200 источников,
прямые пробы живых API). Полные отчёты — в транскриптах сессии; здесь —
load-bearing факты для решений.

## 1. CMS-плагины: категория «крипто-чекаут» мертва, шаблон UX найден

- Весь крипто-PSP на WooCommerce: ~11.6K установок против 800K у PayPal
  (0.15–0.4% пенетрации). Coinbase Commerce закрыт 2026-03-31 — 4 000
  магазинов до сих пор гоняют плагин в мёртвый API; BitPay в maintenance
  mode (200 установок), кладбище модулей под остальные CMS.
- **Урок «минут»**: Coinbase Commerce обещал «4 минуты» только потому, что был
  self-custodial без KYC. У BitPay плагин — 5 минут, KYC — 5–7 рабочих дней
  с пачкой документов. Узкое место — аккаунт/кастодия, не софт.
  → Наш non-custodial дизайн = структурное условие минутного onboarding.
- **Шаблон идеального подключения** (никем в платежах не занят):
  PayPal Integrated Sign-Up — одноразовый `action_url`, лайтбокс, PKCE-обмен,
  креды забираются программно, **ноль скопированных секретов**. Плюс у
  WooCommerce ~10 лет существует неиспользуемый one-click key grant
  `/wc-auth/v1/authorize` (app_name, scope, return_url → consumer key/secret
  по approve мерчанта).
- **Каталог WooCommerce читается вообще без плагина**: Store API
  `/wp-json/wc/store/v1/products` публичен по умолчанию на ~7M магазинов
  (`permission_callback => __return_true` в ядре).

## 2. Синдикация каталогов на карточные агент-поверхности — занята и бесплатна

- Stripe (v10.9 Woo-плагина): agentic-commerce подсистема — фид, order mapper,
  15-мин инвентарь. PayPal (v4.1.2): Store Sync **включён по умолчанию**
  (US-gated) + входящие agent-endpoints `wc/v3/agentic`. Shopify: Agentic
  Storefronts default-on с 2026-03-24, мерчант не делает ничего; Agentic Plan
  — бесплатный вход для брендов с любых платформ. WooCommerce core: ACP-роуты
  и MCP-деревья под фиче-флагами. Ещё: Firmly (Best Buy, ~45 мин, no-code),
  getcatalog.ai, xpay.
  → **В card-rail синдикацию не идём: инкумбенты раздают её бесплатно внутри
  плагинов с 700–800K установок.**

## 3. x402-ниша: подтверждённо пуста

- x402-плагины для CMS: claw-pay (<10 установок, 3% комиссия, «вставь адрес
  кошелька» — правильная цель по трению), один GPL-club плагин, 1-commit
  gateway. awesome-x402: «No dedicated CMS plugins documented». xpaysh (8
  платформ) сознательно пропускает x402. Инкумбенты сеттлятся в карты.
- **У x402 нет семантики заказа вообще** (корзина/позиции/адрес/фулфилмент).
  Кто моделировал заказы — OpenBazaar (`contracts.proto`) и Nostr NIP-15 —
  умерли об одно и то же: **мерчант должен держать листенер**.
  → Разрыв №1: x402-native order bridge, где листенер хостим мы, а мерчанту
  заказ приезжает в канал, который он уже читает (email/telegram/дашборд),
  с confirmation-бекстопом (паттерн DoorDash: email/fax + контрольный звонок
  — жив в 2026, tablet fee за него не берут).

## 4. Zero-consent модели: работают технически, мертвы юридически

- Amazon Buy for Me (400K+ мерчантов без согласия): каталог ошибок —
  out-of-stock продажи, чужие фото, возвраты на мерчанте. Rye: честные цифры
  браузер-агентов на произвольном мерчанте — **65% надёжности, 5 мин,
  35% ручной доводки людьми**; антифрод-системы мерчантов — главный блокер.
- Прецедент финала: DoorDash/Grubhub non-partner листинги → CA AB 2149
  (2021), FTC v. Grubhub $25M (2024), Chicago v. Uber $10M; DoorDash 10-K:
  практика прекращена как дорогая и ошибочная. Amazon v. Perplexity
  (2026-03-10, prelim. injunction): **согласие пользователя ≠ авторизация
  мерчанта**.
  → Consent-first — не вкус, а юридическая необходимость. Zero-consent не
  строим ни в каком виде.

## 5. Gift cards как универсальный рельс — занято и без маржи

Bitrefill + Cryptorefills уже продают через x402 (анонимно, без ключей);
плюс Reloadpi/GiftPulse/Laso. Маржи для четвёртой стороны нет (дистрибьютор
~3% съеден выше; агент платит +0.3…+13.9% к номиналу), покрытие ~2–3K
реальных брендов, ноль B2B/услуг, AML-потолок $500/день анонимно, у
Bitrefill запрет перепродажи. Redemption всё равно ручной.
→ Не наш рельс. Но их «9 merchant playbooks» (Cryptorefills
`agentic-commerce`) — читать при проектировании фулфилмента.

## 6. Услуги и офлайн: полностью открыто, и почему

Ни один слой agentic-стека не покрывает услуги. Телефонные агенты за 8 лет
(Google Duplex → Ask for Me) так и не размещают заказы; TCPA = $500–1500 за
звонок без согласия. Human-in-the-loop консьержи: цена задачи не сдвинулась
за 8 лет ($10–32 у Fin'2018 = $16–25 у Duckbill'2026).
**Рабочий прецедент — Groupon**: контракт за 2–4 дня, ноль интеграции,
продаётся **право на будущую услугу**, «redemption триггерит выплату».
→ Структурно это и есть x402-примитив: pay first → entitlement. Связка
никем не построена. Кандидат на модель услуг в Coinslot v2.

## 7. Неудобная находка: спрос, а не трение

- Реальная x402-коммерция ~$28K/день, ~50% активности — wash/gamified;
  ни один крупный мерчант не выставил x402 как потребительский способ оплаты.
- OpenAI свернул Instant Checkout: конверсия в чате ~⅓ от сайта мерчанта
  (при 2× new-customer rate) — AI хорош в discovery, плох в закрытии сделки.
- Onboarding-трение на CMS решают капитализированные инкумбенты прямо сейчас.
→ Строить рельсы онбординга — правильный инстинкт, но давление проверять
надо на стороне спроса: кто покупает. Пилот-метрики ADR-0001 (единицы
вызовов/мес = успех) — адекватны рынку. Демо-спрос генерим сами (наши
агенты как первые покупатели).

## 8. Мелочь, подтверждающая продукт

Уже существует платный сервис «bazaar-keepalive» ($190/год) — ровно наш
«пульс листинга». Операционная обязанность из 05-merchant-contract.md — вещь,
за которую рынок уже платит.

## 9. Регуляторная линия (US) — где проходит граница нашей модели

- FinCEN (FIN-2019-G001): **CVC payment processor = money transmitter** —
  «принял крипту пользователя и заплатил третьему лицу-мерчанту» требует
  MSB-регистрации + ~49 штатных лицензий. Paxful (10 лет, масштаб) умер в
  ноябре 2025 от «unsustainable compliance remediation costs» после
  unregistered-MSB энфорсмента.
- **Наша конструкция другая по построению**: Coinslot не принимает и не
  передаёт средства — `payTo` = кошелёк мерчанта, settle делает фасилитатор,
  деньги идут agent→merchant напрямую. Non-custodial здесь не только UX
  (минутный onboarding), но и регуляторная стратегия. Требует юр-проверки
  перед продакшеном, но линия «никогда не касаться денег» — архитектурный
  инвариант №1.
- Redemption-последняя миля закрывается для «серых» агентов: Amazon
  перечисляет GPTBot/ClaudeBot/PerplexityBot поимённо в robots.txt
  (Disallow: /), Ninth Circuit 2026-08-04 отменил injunction Amazon v.
  Perplexity узко («браузер пользователя ≠ CFAA-доступ»), ToS-энфорсмент
  остался; Cloudflare шипит классификацию агентов и AI Labyrinth. Индустрия
  сходится к **идентифицированным авторизованным** агентам — consent-first
  Coinslot по ветру, а не против.
- UX-жемчужина: SKILL.md Bitrefill (v3.2.0) содержит слой «языка для
  пользователя» — агенту запрещено говорить «x402», «MCP», «invoice».
  Сложность прячут даже на уровне словаря. Перенять.

## Что это меняет в наших планах

1. Onboarding WooCommerce-мерчанта проектируем по шаблону: **Connect-кнопка →
   OAuth/wc-auth → каталог читаем сами через Store API → витрина
   сгенерирована**. Плагин нужен минимум — только для создания заказа
   (fulfillment), и то можно через granted REST-ключи без плагина.
2. Полоса Coinslot: **x402-native order bridge + hosted listener + доставка
   заказа в существующий канал мерчанта**. Card-rail синдикация — не наша.
3. Order-семантика поверх x402 — наш слой (у протокола её нет); смотреть
   NIP-15 как минимальный конверт заказа.
4. Услуги: держать Groupon-модель (entitlement + redemption) как v2.
5. В ADR-0002/питчах: consent-first обязательно, zero-consent юридически
   закрыт (AB 2149, FTC, Amazon v. Perplexity).

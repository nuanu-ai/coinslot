# 0003. Стек: TypeScript-монорепо на минимальном инструментарии

Дата: 2026-08-26
Статус: accepted (Дмитрий, 2026-08-26)

## Контекст

Стек выбирается под два продукта в одном репозитории: платёжно-смежный
гейтвей (402-край, очередь заказов, квитанции) и мерчантский SDK, который
ставят себе посторонние инженеры. Донор культуры и части выбора —
разбор schematic (`docs/research/13-schematic-culture-stack.md`), позиция
с аргументами — `docs/research/15-culture-stack-position.md`.

## Решение

1. TypeScript strict (расширенный набор флагов schematic), Node ≥24, ESM.
2. Монорепо pnpm workspaces без оркестратора; разрез: `packages/core`
   (домен, ноль IO), `packages/contracts` (zod-схемы — исток истины),
   `packages/sdk`, `apps/gateway`.
3. Линт и формат — Biome одним инструментом, preset задан явно.
4. Тесты — vitest. Тестовый раннер — dev-зависимость и в публикуемые
   пакеты не попадает, поэтому дерево зависимостей SDK (п. 8) им не
   затронуто; выбор по DX: тесты монорепо — читаемая документация для
   стороннего инженера. Разделение: `pnpm test` — бесплатно,
   детерминированно, без сети; всё, что трогает чейн/фасилитатор/живой
   API мерчанта, — отдельная команда smoke с потолком расхода.
5. Валидация — zod на всех внешних границах; публичный контракт
   дополнительно экспортируется как JSON Schema.
6. Хранилище — один Postgres, drizzle + drizzle-kit. Очередь заказов
   пилота — в том же Postgres, но через готовую библиотеку очереди
   (класса pg-boss: ретраи, backoff, отложенные задания из коробки),
   не самодельный механизм на SKIP LOCKED. В ядре очередь — порт;
   триггеры переезда на выделенный брокер названы заранее: второе
   желание дописать руками фичу поверх очереди, измеренный провал SLO
   доставки, fan-out на нескольких независимых потребителей события.
7. 402-край пилота — на официальном x402-сервере (express-образный);
   доменная логика фреймворка не знает, край заменяем.
8. Версионирование и публикация SDK — changesets. Дерево
   runtime-зависимостей публикуемых пакетов держим минимальным и
   перечисляем явно: сегодня это наши `@coinslot/contracts` и zod —
   валидация на внешней границе входит в работу SDK, а писать её руками
   запрещает правило самоделки (п. 9). Каждый новый сторонний пакет в
   этом дереве — отдельное записанное решение. «Ноль зависимостей» в
   документации не обещаем. Ограничение касается только публикуемых
   пакетов: гейтвей использует библиотеки свободно.
9. Правило самоделки (страховка от «упростили, а потом построили своё»):
   желание написать руками кусок инфраструктуры — очередь, ретраи,
   целостность, шедулер — читается как сигнал неверно выбранного
   компонента, не как задача на реализацию. Каждое упрощающее решение
   обязано нести список «что не строим руками», готовый компонент на
   замену и заранее названный триггер апгрейда. Граница: домен (леджер,
   идемпотентность, машина состояний заказа) строим сами — это продукт;
   инфраструктуру-коммодити берём готовой.

## Последствия

- Плюсы: минимум слоёв (уроки schematic оплачены не нами), совпадение с
  экосистемой x402 (официальные SDK — TS), SDK с коротким явно
  перечисленным деревом зависимостей (contracts и zod) как аргумент
  доверия мерчанта.
- Платим: dev-цепочка vitest тяжелее голого node:test; очередь в
  Postgres имеет потолок; express-край — не самый современный выбор.
  Всё — с названными заранее стоп-сигналами для пересмотра.
- Отклонено: Rust/Go для ядра (второй язык на пилоте), Turborepo/Nx
  (до измеримой боли сборки), Hono/Fastify (интеграционный риск против
  нуля пилотной пользы), Redis/Kafka сейчас (вторая шина рядом с
  леджером без измеренной нужды), node:test как аскеза (аргумент
  «зависимость в SDK» не выдержал проверки — тестовый раннер не
  публикуется), самодельная очередь на SKIP LOCKED (правило самоделки),
  агентный каркас pi и Next.js-консоль (нет предмета на пилоте).

# Первая продажа

*Предварительная версия контракта — до пилота формулировки могут уточняться.*

Эта страница написана для инженера мерчанта и описывает путь от пустого
проекта до первой тестовой продажи. Ваш магазин при этом не переписывается и
даже не трогается: рядом с ним появляется небольшой обработчик, который
получает оплаченные заказы и отдаёт по ним товар.

Дальше встречаются четыре слова, которые стоит определить сразу. Карточка —
описание товара в каталоге, по которому агент принимает решение и совершает
покупку; её поля разобраны в [справочнике карточки](/cards). Заказ — объект,
который появляется у нас после покупки и приходит на вашу сторону. Воркер —
ваш процесс, который подписан на заказы и выполняет выдачу. Ключ
идемпотентности — строка, одинаковая при всех повторах одного и того же
заказа: по ней ваша сторона отдаёт тот же результат вместо второй выдачи.

::: warning Поверхность инструментов предварительная
Имя пакета, имена функций и имена полей в примерах ниже — рабочие. Решением
зафиксирована модель интеграции, а не сигнатуры: из имён полей окончательны
только `merchant_item_id`, `as_of` и наш каталожный `id`. Остальное до пилота
может измениться, и об изменениях мы предупреждаем заранее.
:::

## Поставить инструменты

Всё, что нужно вашей стороне, лежит в одном пакете. Runtime-зависимостей у
него нет — это осознанное ограничение, чтобы установка нашего пакета ничего
не приносила в ваш проект вместе с собой.

```sh
npm install @coinslot/sdk
```

Ключ доступа к нашему API вы получаете при подключении и держите там же, где
держите остальные свои секреты.

```ts
import { createClient } from '@coinslot/sdk'

const coinslot = createClient({ apiKey: process.env.COINSLOT_API_KEY })
```

Как устроена авторизация вызовов и подписи запросов в вашу сторону —
уточняется, это отдельное решение.

## Описать товар

Карточку вы заливаете к нам сами: мы не ходим за ней на ваш сайт и не
вычитываем её краулером. Ошибки проверки возвращаются в ответе того же
вызова, так что цикл правки короткий и не требует ждать никакого разбора.

```ts
await coinslot.catalog.publish({
  merchant_item_id: 'access-monthly',
  title: 'Доступ к сервису на один месяц',
  description:
    'Что покупатель получает, для какой задачи это годится и что в это не входит.',
  price: { fixed: '5.00', currency: 'USD' },
  params: {
    email: { type: 'string', required: true, title: 'Куда прислать доступ' },
  },
  fulfillment: 'sync',
})
```

Поле `merchant_item_id` — ваш собственный идентификатор товара, тот же, что
у вас в базе. Мы заводим рядом свой каталожный `id`, но ваш ключ остаётся с
карточкой навсегда, и по нему вы связываете заказ со своим товаром без
таблицы соответствий.

Цена в примере фиксированная. Если она у вас считается на лету — от курса,
от себестоимости поставщика, от наличия, — вместо фиксированной цены в
карточке указывается хук цены и наличия: ваш маленький эндпоинт, который мы
спрашиваем в момент покупки. Его контракт описан в
[справочнике карточки](/cards), там же — правила про `as_of` и про то, что
происходит, когда хук молчит.

Значение `fulfillment` объявляет режим выдачи, и агент видит его до оплаты.
Режим следует из того, как вы выдаёте товар, а не выбирается по вкусу:
подключённый API выдаёт синхронно, заказ, который подтверждает человек, —
с подтверждением.

## Принять заказ

Заказы живут в очереди на нашей стороне, и вы забираете их оттуда подпиской.
Хостить приёмник вы не обязаны: соединение открывает ваш воркер, поэтому ни
публичного адреса, ни входящих портов для этого не нужно. Каким именно
соединением это сделано внутри — уточняется, на код обработчика ответ не
влияет.

```ts
coinslot.orders.subscribe(async (order) => {
  const access = await grantAccess(order.params.email, {
    idempotencyKey: order.idempotency_key,
  })

  if (!access.ok) {
    return { refused: { code: 'out_of_stock', message: 'Мест на тарифе нет' } }
  }

  return { delivered: { access_url: access.url } }
})
```

Внутри обработчика вы либо возвращаете выдачу, либо отказываетесь. Отказ —
нормальный, ожидаемый исход, а не авария: в синхронном режиме он происходит
до списания, и деньги покупателя не двигаются. Что именно бывает при отказах
и молчании, разобрано на странице
[«Что может пойти не так»](/failures).

Доставка заказов гарантирует «не меньше одного раза», и это значит, что один
и тот же заказ может прийти в обработчик повторно — после сетевого обрыва,
после перезапуска воркера, после нашего ретрая. Поэтому ключ идемпотентности
не украшение: прокидывайте его в свою систему выдачи и отдавайте по нему
прежний результат. Если ваш API уже принимает такой ключ, достаточно
передать наш.

Жизнь заказа целиком — что приходит в обработчик, когда двигаются деньги,
какие сроки и чем заказ может закончиться — разобрана на странице
[«Заказы и режимы выдачи»](/orders). Точные имена полей заказа и формат
отказа — уточняется, вместе с остальной поверхностью инструментов.

Подписка — способ доставки по умолчанию, но не единственный. Решением
названы ещё два: доставка заказа запросом на ваш адрес, если у вас уже есть
инфраструктура для входящих запросов, и пакетная выборка по курсору для тех,
кто обрабатывает заказы партиями. Оба живут над одним и тем же объектом
заказа и переключаются без переписывания выдачи. Их поверхность в
инструментах — уточняется.

## Проверить себя

Перед тем как звать нас, прогоните проверку. Она смотрит на две вещи: хватает
ли карточки, чтобы агент сумел составить корректную покупку, и держит ли ваш
обработчик идемпотентность — то есть даёт ли повтор одного заказа тот же
результат вместо второй выдачи.

```sh
npx coinslot verify
```

Проверка объясняет каждую находку словами и указывает на конкретное поле или
конкретный ответ обработчика. Молчаливого «невалидно» здесь нет: если
карточку нельзя опубликовать, из вывода понятно, что именно дописать.

## Тестовая покупка

Первая покупка вашего товара делается не живым агентом, а нашим песочным
покупателем — программой, которая проходит весь путь целиком: находит
карточку, спрашивает цену, платит и принимает выдачу. Это не имитация
отдельных шагов, а настоящая покупка на тестовых деньгах, и после неё видно,
что связка работает вся, а не по частям.

Как именно она запускается — командой из ваших рук или нашей стороной по
вашему сигналу — уточняется, как и то, чем разделены песочница и боевой
режим: отдельным окружением, флагом в карточке или отдельным вызовом.

## Публикация

Карточка уходит в каталоги после того, как тестовая покупка прошла, и до
этого момента снаружи она не видна. Полноту карточки перед публикацией
проверяем и мы со своей стороны — по ней агент должен суметь купить.

Дальше подключение новых каталогов, переезды на новые форматы обмена и
правки карточек при смене товаров и цен — наша работа, и вашего кода они не
касаются.
